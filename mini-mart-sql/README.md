# 角落選物 MINI MART

商品與庫存 SQL 實驗室——資料庫管理實作作業。

本作品以便利商店店長的日常問題為情境，使用商品、供應商、進貨與銷售資料，查詢熱銷商品、營收、現有庫存及補貨需求。所有商店、商品交易及供應商聯絡資料均為教學用模擬資料，資料基準日為 **2026 年 11 月 18 日**。

## 功能與作業對應

| 教授要求 | 本作品的內容 |
| --- | --- |
| 案例背景 | 使用對象、商店情境與想解決的管理問題 |
| 資料庫設計 | 六張資料表的 ERD、主鍵／外鍵、欄位型態與用途 |
| 樣本資料 | 可查看實際載入查詢引擎的資料 |
| 查詢操作 | 提供自然語言問題、SQL、預期結果，並允許修改後執行 |
| 實際結果與錯誤 | SQL 由瀏覽器內的 SQLite 引擎實際執行；顯示查詢結果或引擎錯誤 |
| 同題結果比較 | 比較修改前後的 SQL、結果差異與原因 |
| GitHub Pages | 以靜態網站發布，不需另外架設資料庫伺服器 |
| 能說明自己的作品 | 搭配交付檔「作品說明與報告準備.md」理解設計與結果 |

## 操作方式

1. 閱讀案例背景，理解商店想解決的問題。
2. 查看資料庫關聯、欄位說明與樣本資料。
3. 在 SQL 練習區選題，先看問題及預期結果。
4. 執行題目提供的 SQL，再修改條件或查詢方式，觀察實際結果。
5. 到結果比較區，閱讀同一問題的原寫法、修正寫法及原因。

SQL 編輯框並非按題號回傳固定答案。編輯後的內容會交給 **sql.js／SQLite** 執行。預期結果用來說明標準查詢應得到的答案；實際結果則取決於你本次輸入的 SQL。

可試著將查詢的價格門檻改小、改變排序，或輸入不存在的欄位名稱，確認結果與錯誤訊息確實跟著改變。SQL 語法以 SQLite 為準，與課本的 PostgreSQL／MySQL 在部分函式及語法上可能不同。

## 資料模型與計算規則

| 資料表 | 角色 |
| --- | --- |
| `categories` | 商品分類 |
| `suppliers` | 供應商基本資料 |
| `products` | 商品、目前售價、期初庫存與補貨門檻 |
| `stock_receipts` | 各商品的進貨紀錄與進貨單價 |
| `sales` | 銷售單時間及完成／取消狀態 |
| `sale_items` | 銷售單內的商品、數量與當時成交單價 |

計算時遵守以下規則：

- **現有庫存＝期初庫存＋進貨數量－已完成銷售數量。** 期初庫存代表進貨、銷售紀錄開始前的數量。
- `sales.status = 'completed'` 才計入銷售量及營收；`cancelled` 代表沒有完成交易，不扣庫存。
- **營收＝已完成銷售明細的 `quantity × unit_price` 加總。** 使用 `sale_items.unit_price` 保留當時成交價，不以商品現在的售價回算歷史營收。
- 商品與進貨紀錄、商品與銷售明細都是一對多關係。計算庫存時，先分別彙總進貨與完成銷售，再與商品連接，以避免重複加總。
- 每項商品有一個預設供應商。本作品未處理多供應商採購、退貨、報廢、盤點調整及稅額，適合用來解釋課堂查詢。

本作品是查詢與分析示範，不提供真實門市交易、付款或登入服務。每次按下執行，都會獨立重建同一份樣本資料庫；修改資料的實驗不會更新 GitHub 原始資料，也不會影響下一次查詢。若要觀察修改結果，請在同一次執行中先寫 UPDATE 等修改敘述，再接 SELECT。

## 在自己的電腦預覽

請保留整個網站資料夾的結構。直接雙擊 `index.html` 可能因瀏覽器的本機檔案限制而無法載入資料或 SQL 引擎，建議透過本機網頁伺服器開啟。

若電腦已安裝 Python：

1. 在這個資料夾開啟終端機。
2. 執行 `python -m http.server 8000`。
3. 在瀏覽器開啟 `http://localhost:8000`。
4. 結束預覽時，在終端機按 `Ctrl+C`。
